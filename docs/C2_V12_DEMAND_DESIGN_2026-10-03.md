# C2 v12：需求处置与共同控制底座（设计卡）

2026-10-03。作者修订，设计/实现待审。先读本卡与fixtures/room_v12/inputs.json，不先看规则成绩。继承v4的未校准物理参数与时钟，不修改旧冻结版本。

## 请求语义

air不再无条件要求开窗：当前CO₂≤900ppm且窗关闭时，合法处置是保持关窗，允许noop或无未来等待时刻的defer，形成request_satisfied_without_actuation终态。未发出开窗命令，不计action_completed，命令完成false、时延null。CO₂>900ppm则须通风并由共同可信控制器达标后闭窗；没有动作不能算正确处置，低CO₂却开窗会因ventilation_not_needed被拒绝。

required_action/action_grounding只描述需要执行时的开窗命令，不把合法不执行当成开窗完成；demand_rule明确何时该命令必要。公开工具包含CO₂>900的开窗前提、固定成本；不是依赖脚本私下选择而任务仍无条件要求命令。供暖请求仍要求授权启用命令，环境温度服务另判；本版未扩展已达温度后的供暖跳过语义。

所有命令请求截止新增明确为360000ms，与环境期限同刻；空气发布0、供暖发布100ms。请求截止只是本版处置/命令时间口径，不把设备确认当环境目标完成。旧v4没有这些命令截止，不回写旧数据。

## 指标分层

| 层次 | 字段／含义 |
|---|---|
| 合法准入 | task_admission_legal：合法无动作终态、合法预约或供暖准入等待；不代表实际完成 |
| 处置终态 | task_correct_disposition、task_disposition、task_disposition_latency_ms、task_disposition_deadline_met |
| 命令执行 | 原task_correct_action_completed、task_completion_latency_ms、task_deadline_met，只认真实动作回执 |
| 环境服务 | environment：温度/CO₂/关窗首次联合达标，期限快照、迟到、未完成null |
| 代价 | 同期限和共同终点的累计供暖能量、开窗供暖量、温度/CO₂偏离积分 |

处置终态仅分satisfied_without_actuation、command_completed、unresolved。高CO₂命令完成说明合法处置执行已结束，不说明空气或环境服务当时达标；供暖合法等待可准入true而尚无处置终态。它们不是泛化“完成所有用户环境需求”的合并成功指标。不使用旧task_service/served_task_count等命令兼容字段表示需求满足率。

低CO₂跳过：处置可以成功、时延300ms，而命令保持false/null/按时false。高CO₂无动作：处置未决false/null，环境服务也可能未完成。低CO₂错误开窗被拒绝，即使供暖最终使环境目标达标，处置仍不自动变正确。合理拒绝错误提议不冒充通风任务正确处置，也不归为额外实机安全事件。

## 共同授权与成本

SyntheticResident明确委托共享可信控制器。立即供暖与通风后供暖两臂具有完全相同的传感器、闭窗、理想恒温与工具能力，只改变heat_admission规则。规则是共同底座的预设干预，不是LLM推理或第二Agent功劳。

| 权限／成本 | 两臂冻结值 |
|---|---|
| 传感器 | 温度、CO₂、窗/供暖状态；观察tick1000ms |
| 自动闭窗 | CO₂≤900首次观察后请求，3000ms后确认；闭窗命令能量0Wh |
| 理想恒温 | 目标21°C、2kW；目标夹持、等效开启时间计能量；额外开关成本0Wh |
| 供暖准入 | 立即，或等待CO₂达标且窗已确认关闭；额外规则计算时间0ms |
| 提议与命令 | 脚本300ms、命令确认100ms；开窗作业2000ms、供暖作业1000ms，命令资源/能耗0 |
| 环境期限／终点 | 360000／900000ms；不因提前达标截断积分 |

零额外能量/计算成本是合成假设，不是实测免费；持续供暖能量已由物理环境按等效开启时间计费，不能再按命令重复计。闭窗确认的3000ms真实计入热交换与等待。立即供暖允许开窗供暖，非硬违规；代价体现在能量/温度偏离，不把open_window_heater_wh自动叫浪费。
