# 依赖任务 v11：设计修订卡

2026-10-03。作者修订，设计和实现尚待复审。请先审本卡、inputs.json与certificates.json，不先看策略成绩。沿用HC-M12合成洗涤→烘干结构；不改变v3或已有冻结成绩。

## 核心合同

wash与dry属于显式的同一逻辑批次batch_1。wash发布0ms，dry发布100ms（LATE为5000ms）；各作业4000ms，洗涤资源1.5、烘干2.0，命令确认100ms、默认脚本提议300ms。常规截止15000ms，资源容量6。洗涤获合成住户授权时才可执行；烘干必须先收到同一批次、有效洗涤尝试的真实成功回执。可信底座管理依赖，不是LLM输出决定回执可信性。

固定单批次映射，不支持多批衣物身份切换、并发多次洗涤或任意DAG工作流。尝试以proposal_id区分；动作结束必须与真实启动、grounding和有效性历史匹配。laundry.washed=true仅是可观察状态，不足以释放依赖。取消、失败提议、已失效尝试的自然物理结束或旧取消完成回执都不产生可信前驱成功。

默认生命周期政策是restart_from_zero；授权恢复使同请求新尝试从零执行。CANCEL族采用withdraw：撤回原洗涤请求后，即使恢复授权也不复活，烘干明确blocked。两种合同都是SyntheticResident的显式合成政策，不称实机物理限制或补偿结论。

## 配置与配对

| 配置 | 变化／审查用途 |
|---|---|
| EARLY | 基础早发布；依赖等待不算错误 |
| LATE | 仅dry发布改为5000ms |
| INFEASIBLE_8000 | dry截止8000ms；不可行压力诊断，排除于可行全按时成功分母 |
| FEASIBLE_8500 | dry截止8500ms，具有构造性可行排程 |
| CANCEL_NO_RESTORE / CANCEL_RESTORE | 固定withdraw，1000ms撤权；只增删5000ms恢复事件 |
| RESTART_NO_RESTORE / RESTART_RESTORE | 固定restart_from_zero，1000ms撤权；只增删5000ms恢复事件 |
| INVALID_PROPOSAL | 300ms返回的wash提案，仅operation由wash改为unsupported |
| FORGED_STATE | 450ms伪造laundry.washed=true，不伪造可信执行事件 |
| STALE_NATURAL_RACE | 4000ms撤权、确认1000ms；自然结束先于停止确认，5000ms恢复 |
| CAPACITY_TIGHT / CAPACITY_SAFE | 独立第三负载dishes：发布0、作业8000ms、资源1.5、截止15000；容量3/6 |

13配置，每配置四策略，52开发回放。全部统一观察终点16000ms。容量变化同时更新conflict_rules里的派生capacity字段，是同一资源上限的两处表达，不是新增因素。dishes无依赖边，先验独立；不把wash/dry必要串行误当容量冲突。

CANCEL与RESTART跨族比较会改变政策，不能称单因素；恢复事件效应只在同模式内配对。EARLY/INVALID_PROPOSAL是合法/非法输出诊断对照，输入与非注入输出一致，不算新增任务结构，不额外补调用。

## 可行性与时间口径

公开参数下，wash最早400→4400ms，收到真实回执后dry命令确认100ms，最早4500→8500ms。故8000ms期限低于最早物理完成时间，不用方法共同失败证明优势或在线不可避免损失。8500ms恰好可行，不保证所有策略都找到最早排程；方法的等提议或排队时延不能写进“任务不可行”的定义。

时间必须区分绝对物理结束与自发布时延：基础dry8500ms结束，发布100ms，所以完成时延8400ms。LATE可5400→9400ms。恢复后wash5100→9100ms，dry9200→13200ms。容量3的可行证书允许wash400→4400、dishes400→8400（总3），dry8500→12500；容量6可dry4500→8500。证书仅证明冻结开销和合成授权下存在排程，不是所有在线策略成功保证。

撤权与停机：即时检测、请求容限0、静止容限200、参考确认窗口200ms；默认实际确认200，竞态1000。旧尝试失效立即生效，不等停止确认；自然结束只写设备静止，不能写laundry.washed或service成功。恢复的新尝试才可生成依赖回执。与自然结束同刻采用右开区间，不追溯撤销已有效完成。

## 失败和评分口径

INVALID_PROPOSAL是严格工具授权拒绝诊断，不是运行中的硬件失败。注入动作返回300ms，预期tool_not_authorized；方法可能延迟到派发时校验，返回与拒绝时刻分别记录。没有洗涤成功回执，dry留在dependency_waiting；洗涤未成功不自动等于终态执行失败，不强行传播blocked。CANCEL则明确终态撤回，因此后继blocked。无恢复洗涤pending_validity，dry等待依赖；三类不要混计。

逐任务分别记录真实首次启动等待、有效完成、完成时延/迟到/按时。未完成false/null、合法撤回单列、必要排队仍按时即服务成功。物理暴露、参考窗口及额外暴露另计；恢复成功不抹去旧暴露。前驱成功不是普通状态字段，不认旧或伪造回执。

## 公平输入与结论边界

四策略共用严格工具、可信回执、安全门、静态公开成本和局部观察。公开身份HC-M12、请求ID无配置标签；去掉模板答案、任务私有评估字段、未来事件与恢复条件。脚本从公开工具提案，不读私有grounding。batch_id公开；依赖执行由共同底座承担，不由额外Agent赋予权限。

参数是抽象资源/服务合同，不是洗涤物理或实机能耗；未打开保留集、未调用模型。诊断不是独立任务结构计数。先冻结本设计，再看[实现审查包](DEPENDENCY_V11_REVIEW_PACKET_2026-10-03.md)，通过之后才考虑C2需求语义；暂不启动新模型实验。
