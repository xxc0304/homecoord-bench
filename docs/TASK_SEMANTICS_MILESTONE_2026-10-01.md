## C1：持续有效请求，不是同时满足矛盾动作

保护请求有效至 6000 ms；高优先级场景服务开始于 400 ms、完成于 900 ms。低优先级相反请求在 1200 ms（冲突）或 6500 ms（安全）发布。两组仅改变这个发布时间；权限、状态可见性、工具、时长和截止完全相同。

冲突组中两条命令本来不重叠，依然不得在保护窗口内关灯/开帘。工具前提声明 request inactive，启动时复核。低请求应拒绝，高请求完成：**正确处置为真，但低请求动作完成为假，其完成时延为 null。**安全组两请求均完成。不能用“全部动作完成率”惩罚合理拒绝，也不能把拒绝记成动作服务。

双方都看到保护状态，初态安全；不再把低优先级 Agent 的必要信息藏起来。不用照度/温度瞬时跳变证明物理舒适。当前是公开固定优先级的强规则负对照，不是证明 LLM 必需的任务。

## C4：阶段与恢复合同分开

固定提案延迟 300 ms、命令延迟 100 ms、服务持续 3000 ms；任务开始 400 ms、自然完成 3400 ms。单位是作者定义的抽象服务时间，不是实机测量。

| 情境 | 无效事件时刻 | 当前执行结果 | 可作的结论 |
|---|---:|---|---|
| 无事件 | 无 | 服务完成，无违规 | 正向服务对照 |
| 启动前 | 200 ms | 拒绝工作；完成时延 null | 启动时复核有效 |
| 执行中 | 1000 ms | 检测 1 次前提失效，动作仍完成；违规暴露 2400 ms | 揭示停止能力缺口，不能称安全成功 |
| 完成后 | 4000 ms | 已完成服务，不追溯取消 | 生命周期阶段对照 |
| 无关更新 | 1000 ms | 服务完成，不因版本变化误拒绝 | 检验按相关条件而非版本号盲拒绝 |

独立重放确认完成后的安全终态没有掩盖 2400 ms 违规。降雨事件只改变 raining，不再提高土壤湿度或写服务回执；居民进入也不能完成清洁。第二 Agent 有单独服务回执，但没有改变工作动作，本轮**不证明多 Agent 协作必要性**。

清洁合同：住户离开后可从零重启；灌溉合同：降雨撤回请求，不要求雨后重启。两者都声明停止确认成本 200 ms。**这些恢复合同尚未接入统一运行时，recovery_completed=null，不把缺失结果填成 0 或成功。**下一执行阶段应实现真正停止确认、释放预约、作废旧完成事件、重新发起/撤回与相应计分；不要把旧独立恢复探针当成此处已集成。

边界：本轮验证了五类离散阶段，尚未覆盖恰好开始/完成、同刻停止确认/完成、重复停止等边界；下一阶段一并测试。

## 后续执行顺序与验收

1. **统一 C4 生命周期**：开始前拒绝、执行中 stop 请求与 ack、旧完成事件失效、预约释放、清洁重启/灌溉撤回；同刻边界、重复取消、慢停止确认测试。先脚本与独立审计，不加 API。
2. **补依赖语义；评估 C2 接口可行性**：不同机制独立验收。C2 未取得参数证据时继续探索，不阻塞抽象 C1/C3/C4 主线。
3. **独立双审**：Phase A 审任务/工具/可见信息/来源/配对，不给策略结果；Phase B 审轨迹与评分。真实审阅者姓名/分歧记录尚缺，绝不代填通过。
4. **同信息强规则与负对照**：C1 优先级/有效期锁；C3 在线 EDF/可行性规则；C4 本地安全联锁与恢复。先验证规则足够条件，再挑有研究价值的难例。
5. **任务稳定后再模型**：修接口歧义另登记小预算，重复/第二模型后再测试；不复用用满的 224 请求预算，不打开保留集开发。
