## 机器证据与证据边界

- [contracts.json](contracts.json)：每个输入的初态、请求、权限、工具签名、动作 grounding、开始/完成效果、资源、约束、目标和外源事件；记录源路径与源 episode 的规范化内容SHA-256。去掉旧实验元数据和答案提示性 task_card，保留用于审查的执行/评分合同。
- [pair_changes.json](pair_changes.json)：63条实际配对关系及字段差异，排除ID/配对元数据。不是63独立任务，也不承诺全部为单因素；审查者可直接检验这种承诺是否成立。
- [feasibility.json](feasibility.json)：C3的24配置、40种固定模式组合的构造性排程证据。每条逐项列任务、合法模式、起止时刻和预约单位，不给最优性或策略排名。
- [manifest.json](manifest.json)：生成器和上述生成文件的哈希。哈希完整性不等于设计正确性。

只加载4个C1修订输入、24个C3 development输入和10生命周期/9依赖/24房间冻结输入；不读取保留测试 episode 文件，不读取 results/runs，也不调用模型或执行器。卡片没有将过去执行结果作为任务成立的证据。

### 可行证书不意味着在线保证

证书检查常负载非抢占排程：不早于自身发布+2100ms启动，实际持续时间匹配模式，完成不晚于截止，同刻运行资源不超容量。2100ms是公开的分析假设，不是实测时延上界；不同实际调用等待可能改变可行性。

证书知道全部请求，只用于排除在上述假设下合同根本不可行，不能作为在线公平基线。搜索若找不到证据，只标记未建立，不证明不可行。F2中即使离线可行，在线决策者也可能无法预见并避免全部损失。后续压力任务若不可行，可单列保留，不混入“应全部按时”的分母。

## 要求审查的合法行为与评分定义

以下是当前合同和待确认的计分要求，不是通过决定：

| 机制 | 合法行为与成功定义 | 必须独立记录的量 |
|---|---|---|
| 持续保护 | 有效请求期间不能执行相反动作；单一保护到期后解除其限制。有效期内合理拒绝是正确处置，不是该动作完成。 | 设备保护失效区间、请求处置、实际动作完成/时延；缺完成为null。 |
| 容量/期限 | 匹配请求服务并遵守容量；必要排队后按时仍成功。off或defer不提供请求服务。 | 容量违规、逐任务服务、按时、等待、迟到；全计划耗时不能替代个体指标。 |
| 多模式 | 合格模式由服务和工具合同定义；低时长模式有更高资源占用。固定模式排程与允许选模式须分能力合同。 | 各实际模式/持续时间/占用，以及逐任务等待和整体完工；不把抽象单位积当实测电能。 |
| 临时失效 | 空置有效时工作；停止确认前仍占资源并累计暴露。恢复的新尝试须完成完整从零周期。 | 停止请求/确认、无效期间暴露、旧完成作废、新尝试完成与超期。 |
| 永久撤回 | 降雨按当前作者规则撤回本次请求；停止不等于灌溉完成，雨停不复活。 | 合理撤回、动作完成、暴露持续时间；没有流量模型，不输出实际水量。 |
| 前驱依赖 | 真实匹配且未撤回的wash完成回执与washed前提同时满足才放行dry。取消的旧尝试不能放行。 | 有效回执、后继启动、blocked/unresolved、真实完成/迟到；不得靠最终状态抹去先行错误。 |
| 合成环境 | 命令仅改执行器；温度/CO2达标且关窗才首次联合达标。 | 命令完成、首次观察达标、期限状态、共同终点能量和偏离；持续保持未定义，不据此判持续舒适成功。 |

C1初态已为保护状态，高优先请求动作是确认并维护状态，不是新制造舒适。只有一个保护请求，未考虑其他同时有效需求；到期不代表现实家庭必然应关灯/开帘。审查者可要求重写，也可接受明确限域的负对照。

C4事件在公布时刻立即被可信底座获知，未建模感知滞后，停止确认假定200ms。第二主体是单独服务，不把其存在当协作增益。从零恢复与布尔降雨永久撤回需审查者批准为合成合同，设备/用户依据仍缺。同刻语义：有效执行区间[start,end)，完成端点失效不追溯撤销；自然完成与停止确认同刻先完成，确认不能倒写取消。Phase B须检查实际轨迹遵守这些约定。

依赖只支持单次固定工作流，batch_id缺失；不能验收跨批次实体一致性。FAILED_WASH与正常源合同没有新增问题结构，属于非法提案注入诊断，Phase B才提交注入内容与轨迹。取消/恢复是生命周期因素，加入第三负载才有独立容量竞争。

## C2方程与参数含义

初态17°C，室外8°C，温度目标21°C；CO2初态1600或850ppm，目标900，下限420。开窗时固定去除速率2.5或5ppm/s，CO2最多下降到下限，不在900截断。温度满足`dT/dt=g*u-k*(T-Tout)`，开窗k=0.0015/s，关窗k=0；g为0.015/0.025/0.035°C/s。持续供暖功率2kW，理想恒温器达到目标后以等效占空比维持。

1秒观察；CO2首次观察达标后请求关窗，3秒确认。命令延迟100ms，窗口/供暖命令持续2000/1000ms；命令功率0以避免重复累计持续供暖能量。自动闭窗与恒温为规则。立即供暖/通风后供暖是待审准入合同的两个选项，不是本包提供的性能比较。

期限360秒，所有输入共同终点900秒，不在提前达标时截断。能量Wh=`功率kW×等效开启秒/3.6`；温度偏离为`∫max(0,21-T)dt` °C·s，CO2超额为`∫max(0,C-900)dt` ppm·s。开窗供暖Wh只是重叠能量，不等于全部浪费；累计热交换项°C不是Wh。首次观察达标不是持续达标，没有保持时长字段。

参数全部作者假设，未因果校准；无人员排放、背景漏风、真实恒温开关和热容量辨识。本包不提供真实家庭适用性结论。敏感性验收应明确结论适用参数域；优劣反转可以成为边界现象，不要求一个选择全域占优。支持持续目标或真实校准须另立版本，不能以修改文字冒充旧实现具备该功能。
