# 同模型集中／功能 Agent 开发比较：运行前协议

本轮承接 2026-09-30 集中批次接口，回答集中批次提案、逐任务并发提案及信息汇集怎样影响服务、截止、逐任务等待和 API 开销。只运行已锁定的开发数据，不打开保留测试。本协议在新模型调用前保存。

## 三组与能力合同

| 组 | 每次请求信息 | 调用组织 |
|---|---|---|
| central_batch | 当次发布组全部功能 Agent 的允许视图 | 一组一次，返回每任务最多一个动作 |
| functional_local | 自己的允许视图 | 同组逐任务真实并发 |
| functional_pooled | 自己的视图＋与集中组完全同源的发布组视图列表 | 同组逐任务真实并发 |

三组同用 deepseek-flash、reasoning none、同目标指令、公共 DeadlineAwareCoordinator（当前已发布任务等齐后 EDF）、公共安全门、工具权限和公开成本。集中响应上限 1200×当组任务数，功能每请求 1200；相同逐任务输出上限不等于相同实际 tokens、时延或费用。集中批 schema 的包装指令与单任务输出不同，作为接口差异报告。

集中组与 pooled 组拥有相同视图集合，逐任务职责和输出框架仍不同；局部组本来就可见 coordination_context 中已发布请求的公共成本/期限，不能把它叫完全没有全局信息。新增汇集主要覆盖其他当前发布任务的设备观测、职责和工具详情。只给当前发布组，没有跨批历史记忆、旧设备全局状态、未来请求、取消补偿或模式改写权限。允许模型首次选任一合格模式；执行器不能事后替换。F2 晚到组按各分支的发布现场状态新调用，不复用为其他分支结果。

固定 EDF 是本轮隔离提案架构的主执行策略，不代表完整多协调器或 LLM 协调方法排名。保留提案回放与真实模型新采样的区别。模拟器先在墙钟收集一组，再按共同起点的真实返回偏移推进虚拟事件；功能请求组内并发，尚不是实时在线设备系统。

## 选择、顺序与上限

事前选择六个开发结构 D-F1/F2/F3-01/02，每结构有竞争/无竞争两条件；F1/F3 只选 base，F2 只选 late，不按结果筛选。12 条情境×2 次新采样×3 组＝72 个策略执行单位。每个条件和组都新采样，不跨容量复用。组顺序按预先锁定的轮转表平衡；两次重复仅是小试点，不能估计稳定尾分位数或显著性。

按任务数和发布批次数推导最多 224 次 API 请求（集中 32、局部 96、汇集 96）。每次仅一次尝试，超时 45 秒，无格式或网络自动重试，不补满成功；失败占预算。调用前写持久预算预约，恢复时读取预约与 started 日志。结果已有完成单位则跳过；中断单位拒绝自动重新调用，保留日志供审计。该上限约束请求次数，不是假定已核实美元账单。

运行前锁定开发输入、源划分 manifest、协议和相关实现哈希。新增日期目录和结果文件，不重跑或覆盖 09-30 的 26 次调用试点。完整原始合成请求/回复和错误保存在本机 runs（已 gitignore），聚合结果单列实际服务端 model、attempts、tokens 与失败。密钥只从本机环境变量读。

## 失败与计分

集中组原子校验整批：缺失/重复/未来任务、协议错误、越权、状态版本错误或重复 proposal_id 使整批失败；不部分抢救。功能组只让失败任务失去提案，其他合规任务继续。两者失败范围属于接口机制，应分别报告每调用和每任务失败，不能混为模型能力差异。

调用失败或非法动作以标记为 local_failure_placeholder 的本地 defer 继续公共执行，不冒充模型回复；保留原错误/回复、真实等待成本。明确的模型 off/defer 合法但没有服务分。所有 72 单位均留在分母，逐任务缺失启动/完成为 null；不可跳过失败批次仅比较成功样本。协议合格、授权、语义正确、最终服务、按时和过程安全分别评分。

报告逐任务从自身发布起算的启动等待、完成耗时和迟延；全计划完成、首动作仅为补充。API 实际次数、完整返回时间、tokens、实际返回 model、提供方及本地校验失败分列，缺失 token 记未知而非零。共同执行器本轮不注入完整计算/通信部署成本，模拟墙钟不当架构部署时间。
