# 时延方向小验证：结果与核心命题判断

2026-10-06。作者小规模实验、统计v2与同作者另路重计完成，**尚未独立复审**。这批是新增受控模拟，不是只审查旧轨迹；未调用模型、未打开保留测试进行设计或运行、未上传GitHub。旧材料只做必要来源读取与哈希保护。

## 1. 先回答研究方向是否够核心

**有条件值得推进，但原先那句“跨过不可抢占执行窗口会放大延迟”本身，不够作为顶会核心贡献。** 本轮文献核查已发现：DESBench覆盖共享动态协调；TickingCollabBench覆盖动态异构协作、时间至失败窗口及同步/异步延迟评测；MAFBench分离框架开销；车边调度工作已有批等待/排序拆分；在线承诺与非抢占阻塞属于既有调度问题。不能把家居标签、时间分解或一个临界案例当新贡献。完整链接与差异边界见 `LATENCY_CORE_FEASIBILITY_2026-10-06.md`。

仍有价值的候选核心问题是：**多Agent异步协调中的冲突—时延取舍，能否由决策延迟与可修改执行窗口的匹配预测，而不只由平均耗时或最终调度质量解释？** 原问题不变：共享环境下多Agent协调如何影响冲突、服务与时延。不改为LLM调用时机，也不要求LLM优于规则。

本试点能检验上述问题的必要机制前提。要发展为有竞争力的核心贡献，后续还要做到跨独立结构、实际耗时相关性、分布式信息/执行语义的增量诊断及与既有方法的明确差异；若最后只用经典排程模型就完整解释全部结果，宜保留为benchmark子分析，而不是包装为新多Agent现象。

## 2. 实验范围和公开修正

两个F2模板×容量紧/足×原发布/临近启动，共8世界。原发布3个共同审议延迟点、近启动8个点，共44配置、88正式运行、44对预约处理比较；另24信息诊断，不进服务分母。固定EDF、公开300ms提案、100ms命令、物理时长与权限。只改变共同审议延迟d和retain/replan规则；已启动服务不可取消。每个世界内R/D不变。

近启动世界按旧早期前缀预先设置water发布，使提案返回距原阻塞预约启动有2000ms；自身预算保持、绝对截止随发布时间平移。它是**主动构造的合成边界诊断**，不是自然发生概率估计。其按时率不能与原发布世界直接相减，声称发布时间改变使执行更快。

运行前锁定解析预测；仅使用旧early服务前缀，不读取新water结果，不调用模拟器生成预测。四条新的original/d=0/retain基线精确复现旧预约v1完整调用、轨迹和结果，作为88条中的4条，不重复算样本。旧边界单元测试已可见，不称盲测或独立留出。

原登记把相对零延迟比较数误写为40组/80臂；正确为44配置减8个世界基线，**36组/72臂**。统计预检因此停止，未生成v1汇总。原合同、计划、锁、代码、测试及失败记录保留；v2只修正数量元数据，44个配置及事前预测全部不变，未新增正式重跑。详见 `LATENCY_WINDOW_PILOT_V2_METADATA_CORRECTION_2026-10-06.md`。相邻点比较仍为36组/72臂。

## 3. 观察到了什么

### 3.1 原世界：短延迟并没有必然改变调度

两个原发布、容量紧世界中，d=0/100/2001ms全部实际S/F一致。重排仍使water分别早480/360秒，另一项服务晚120/240秒，全户完工不变。这些延迟都远离可修改窗口边界，被既有资源等待吸收。

容量足的原发布与近启动世界中，water的S/F随d等量后移，两臂始终一致；early与全户完工不变，没有预约机制跳变。它们保留为负对照，不能删除后只展示容量紧临界点。

### 3.2 近启动、容量紧：两个不同的边界

下表为replan的water自身发布到有效完成，单位秒，**同一世界内**比较；不是设备墙钟测量。

| 共同额外审议d（ms） | 模板01响应（s） | 模板02响应（s） | 机制解释 |
| ---: | ---: | ---: | --- |
| 0 | 122.300 | 242.300 | 尚有可修改预约，等待资源释放 |
| 1900 | 122.300 | 242.300 | 扣除100ms命令后，最后一个完全吸收点 |
| 1999 | 122.399 | 242.399 | 预约仍可改，但新命令错过原资源释放点99ms |
| 2000 | 122.400 | 242.400 | 同刻phase3审议先于phase4实际启动，仍可改；新命令后移100ms |
| 2001 | 602.300 | 602.300 | 原阻塞服务已经实际开始，不能再撤销预约，重排效果消失 |
| 3000 | 602.300 | 602.300 | 同一已开始阶段，不只依赖恰好相邻1ms点 |

这里分开了“可撤销窗口”和“命令仍能赶上原可用时刻的窗口”。不是所有d<=2000ms都完全没有代价。

同世界replan从2000变为2001ms时：

| 指标（高d−低d） | 模板01 | 模板02 |
| --- | ---: | ---: |
| water自身响应 | +479.900秒 | +359.900秒 |
| 另一服务响应 | laundry −120.100秒 | cleaning −240.100秒 |
| 全户完工 | −0.100秒 | −0.100秒 |
| 按时服务率 | 4/4→3/4 | 4/4→3/4 |
| 完成服务率 | 4/4→4/4 | 4/4→4/4 |

retain在这两个相邻点的全部S/F不变，water一直迟到。不能把预约处理效应与延迟干预混算。两组replan的water变化来自延迟使既定作业先实际开始；不是新增了物理取消/服务模式变化。

全户完工还略早100ms，是因为未再重排，省去了重新预约后造成的末端平移；它不代表整体更好。这个例子说明：只看全户完成甚至可能掩盖一项服务从按时变为迟到；反过来，只看water也会漏掉另一服务提前的代价分配。

**479.9/359.9秒是本非抢占合成合同的局部跳变，不是“现实中每多1ms就损失几分钟”的普遍结论。** 离散毫秒与phase顺序是明确实现假设，不是实机精度。发生频率、自然到达、实测审议成本与真实设备能否中断均未验证。

### 3.3 预测与正确性

44个配置的water S/F及提交时正在运行/未启动集合，与运行前解析预测全部一致。预测条件化于已知开发early前缀与固定EDF；这既不是跨结构泛化成功率，也不是未知场景的在线最优证明。

88条正式运行都真实完成固定E=4，各世界全部预定槽的共同K=E，覆盖100%；实际容量违规为0。24条未来信息诊断发布前完整输入/执行前缀一致。提交前两臂完整调用及前缀相同；同世界不同d的调用和审议前前缀相同；已实际运行的服务始终保持开始/完成回执。

同作者另路原始事件重计有6301个顶层检查断言通过，含哈希、回执、时间、固定分母、延迟/预约对照、K、诊断与汇总绑定；**不是独立评审，不把断言数当统计证据量**。868项旧保护哈希匹配。实际执行99项相关测试全部通过：25项本批静态/修正/保存轨迹检查及74项旧相关回归。原静态9项在运行前另执行一次，不另算新测试数量。回归单元测试中的额外合成调用不计入88正式/24诊断研究样本。

有效统计入口是v2；原失败v1统计入口及其对应Saved聚合测试不作本批有效入口，文件原样保留。没有运行全仓库自动discover或全套测试，也没有完成独立设计/实现复审。

## 4. 对命题的支持程度

**对机制前提积极，对创新性未新增证明。** 已从旧“预约规则重新分配等待”推进到：相同协调延迟在不同阶段可被吸收、线性传递或导致可修改机会丧失；响应损失同时伴随任务间重新分配，不能只用全户完成或平均开销描述。

但此次解析预测几乎由已知非抢占合同和旧早期区间直接决定。数据支持的是受控合同内的阶段机制，不证明新的调度理论或多Agent必须优于单个普通调度器。两模板仍是同一容量/预约家族，不能凑成多种独立机制；临近窗口主动构造，不能据此估算实际部署收益/风险。

## 5. 后续有门槛地推进

1. 先对新合同、v2计数修正、44个配置、24诊断与逐事件证据做独立限定复审。新scope不能借用上一批通过结论。
2. 复审后才设计F1等待×排序机制分离；事前预测哪个慢Agent会影响哪些服务，同时保留不需等待/容量足/规则成本很小的控制。等待/排序本身不算新颖性。
3. 以另一个有依据、已审的独立执行结构检验诊断能否迁移；另登记实际调用/通信耗时重放或闭环，并检查事件余量分布。当前2秒共同审议不是实测规则或LLM调用成本；历史约秒级API只能提供数量级背景，不能替代本次测量。
4. 若跨结构诊断、实际相关性或与相关工作的差异不能成立，停止把“窗口效应”升级为独立顶会核心贡献，保留为原冲突—时延benchmark的机制子结论。若成立，再扩正式任务/留出/重复，而不是先堆更多临界网格。
