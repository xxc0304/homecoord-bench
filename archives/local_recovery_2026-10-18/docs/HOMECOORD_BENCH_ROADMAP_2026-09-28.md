# HomeCoord-Bench 当前命题与实验路线图

日期：2026-09-28。状态：研究规划；不代表任务已完成，也不预设必须提出新算法。

## 一句话命题

在动态共享家庭环境中，多个专业 Agent 异步提出和执行动作时，协调在什么条件下提高过程安全与任务完成质量，又付出多少响应时延？智慧家庭是可执行载体，论文首先定位为 benchmark；新协调方法只在可信的强基线缺口出现后设计。

## 现状与证据边界

已具备离散事件模拟器、C1–C4 候选机制、强确定性规则、共同安全门控、记录模型提案的反事实回放，以及初步三 Agent 共享容量试验。这些验证了实验流程，并展示了安全、服务、期限和首动作时延并非同一指标。多数任务仍是两 Agent、手工参数；现有三 Agent 试验使用固定名义负载和人工期限，强规则已能解决其构造条件。C2 环境动力学、C3 设备与容量、C4 跨 Agent 信息影响仍需提高证据等级。当前工作目录中的后续试点与本独立仓库尚未完全同步，汇总结果前须逐项核对来源和版本。

## 任务设计：按结构分层，而非 Agent 数量与 C1–C4 全排列

- 基础诊断：两 Agent，分别检验 C1 同设备、C2 间接环境、C3 共享容量，并配无冲突和临界对照。
- 多任务协调：三到五个真正具有不同目标、权限或可见状态的 Agent；涵盖部分并行、不同期限、共享容量、依赖和相互牵连的冲突。不能靠无关 Agent 凑数量。
- 动态执行：在上述任务中叠加 C4，区分提案等待、提交前、运行中和完成后状态变化；明确停止、取消、恢复语义。至少部分变化须由另一 Agent 的报告或动作引起，并实际影响被测 Agent 决策。
- 无冲突配对：与每个冲突任务保持相同目标、设备和提案条件，只改变一个机制变量，用来测量不必要的协调等待。

C1–C3 是冲突机制，C4 是横跨机制的时间维度。不同机制可以合理组合，但不为填满矩阵而制造任务。难度在运行前由任务结构定义，不按某基线是否失败反向筛选。

## 数据与环境里程碑

### 阶段 1：冻结试点协议

交付：任务字段、Agent 可见信息、任务完成契约、动作生命周期、共同安全门控、强基线权限和评分代码的版本化定义。对现有 20 条候选做保留／修订／抽象机制／剔除清单。每个任务先审语义、可行性与参数来源，再看策略结果。

验收：人工审核者能独立判断任务是否可执行、配对是否只改变目标变量；评测器能将“安全拒绝”“任务得到服务”“按时完成”和“最终状态达标”分开。

### 阶段 2：构造结构化试点集

建议先做约 12 个不同任务结构，每个结构产生无冲突、临界、冲突三个配对条件，约 36 个 episode；这是试点规模，不是论文样本量要求。两 Agent 基础题占少数，三到五 Agent 与动态题占多数。参数记录设备规格／模拟器轨迹／项目材料／合成假设的来源等级；无依据参数只用于清楚标注的机制敏感性试验。物理不可行的期限单独标记，不算策略失败。

验收：不同设备名称不被误计为独立机制；任务文本不泄漏标准动作；存在多种合理动作与可自动验证的结果；通过独立审核和确定性回放。

### 阶段 3：补齐环境可信度

优先处理 C2 连续温湿度／空气质量轨迹，C3 分阶段功率和共享容量口径，C4 在途停止与恢复回执。可使用可核查的公开规格、外部模拟器或采样轨迹；没有真实设备时明确分开“来源支持的模拟”和“合成压力测试”。分别测量 API、规则、命令、设备反馈耗时；逻辑异步回放不冒充真实并行调用或现场首动作时延。

验收：任务来源和效果模型可审计；参数扰动与留出工况下结论仍可复现，或明确记录失效范围。

### 阶段 4：基线与主实验

所有策略共用安全门控。基线至少包含无提前协调、设备锁、状态／容量约束、期限／容量感知规则，以及单主 Agent。满信息离线最优只作分析上界。先用同一批保存的模型提案和返回时延比较协调决策，再做完整模型闭环；两类结果分开。分别做固定任务而改变 1／2／多 Agent 分工、固定组织方式而增加任务规模的实验，避免把 Agent 数量与工作量混淆。模型、信息权限和预算差异逐项列明。

主指标：过程安全、全部必要任务服务率、按时率、首次有效动作延迟及尾部延迟、全部任务完成时间、模型与规则耗时和成本。按任务结构与冲突／对照分组报告配对差异；统计独立单位是任务结构或家庭配置，不是同一模板的多个随机回放。

### 阶段 5：论文路线决策

若强规则在审核后的留出任务上接近饱和，先写清其适用边界，继续提升 benchmark 的任务多样性与验证质量，不强造新算法。若在多个独立任务结构上出现稳定的服务、期限与时延取舍，先归因于观测不足、到达顺序、状态变化或调度决策，再针对一个明确缺口设计方法，并在冻结留出集上与强规则比较。不得用为新方法特制的任务作唯一证据。

## 近期执行顺序

1. 核对本独立仓库与最新本地试点的版本差异，确认哪些实验尚未迁入；不混合不同版本结果。
2. 审查现有候选任务，特别是 C2 环境效果、C3 参数来源、C4 真正的跨 Agent 信息作用。
3. 写出 12 个结构化试点任务及配对表，先完成任务契约和盲审，不先挑策略失败案例。
4. 运行共同门控与强规则基线，复核可行性、信息公平和指标口径。
5. 在固定提案回放确认有可解释的条件差异后，再扩展真实模型调用和数据规模。

不将预测执行、模型路由、个性化和新计划修复算法同时塞入首篇 benchmark 主实验；这些保留为后续方法候选。未经用户要求，不上传 GitHub。
